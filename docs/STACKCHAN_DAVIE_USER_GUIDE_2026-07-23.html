DAVIE DESKTOP BODY · QUICK GUIDE

不用找菜单，
直接说 Davie。

Stack-chan 是 Davie 的本地耳朵、摄像头、声音、表情和可转动的头。开机联网后，空闲时直接说 “Davie” 唤醒；官方 Launcher 和 Settings 仍然保留。

基本交互

1 · 空闲时唤醒“Davie”
看到屏幕进入 Listening 后再说完整需求。
2 · 持续对话“How is the weather today?”
Listening 状态下直接讲话，不必再次说唤醒词；Davie 会延续同一设备会话。
3 · 看东西“What do you see?”
摄像头真正拍照后才进行解释，不会假装看见。
4 · 打断在 Davie 说话时直接讲话。短噪声只会进入候选状态；确认是人的持续讲话后，才取消旧语音并延续上下文。

从 Davie 聊天控制

Telegram、飞书、Hermes Web 和命令行使用同一组 Stack-chan 能力。自然地告诉 Davie 要让机器人做什么即可；Davie 会先检查 Gateway 和当前设备会话，不会把“工具已配置”误报成“机器人已经执行”。

聊天需求示例离线时会怎样
检查连接检查一下 Stack-chan 现在能不能用。仍可返回 Gateway 健康与设备是否已唤醒。
让机器人开口让 Stack-chan 说：“该休息一下了。”明确提示空闲时先在设备旁说 “Davie”。
查看面前物体让 Stack-chan 看看面前是什么，不要朗读结果。不伪造画面；提示建立当前设备会话。
预装伴读把这篇 TXT、Markdown 或 HTML 装载到 Stack-chan，先不要播放。可以预装并保留进度，不要求设备在线。
控制设备把 Stack-chan 音量调到 45，头向左转 30 度。不声称动作成功；提示先唤醒。
本地提醒让 Stack-chan 十分钟后提醒我休息。设备本地提醒需要在线；持久任务应改用 Davie 定时任务。
聊天与语音的区别：聊天可以在机器人离线时预装伴读内容和查询 Gateway；即时开口、拍照、音量、头部、LED 与设备本地提醒必须先在空闲的 Stack-chan 旁说 “Davie”，让官方固件建立当前会话。若屏幕已经显示 Listening，直接说需求即可。

屏幕与菜单

不新增一套重复的复杂菜单。默认进入官方 AI Agent 界面，屏幕会用 Listening、Looking、Reading、Speaking 等状态告诉你当前动作。需要配网、音量、开机行为或其他官方功能时，再回到官方 Launcher 与 Settings。

开机行为：Davie 版本在没有用户偏好时默认进入语音待命。如果你在 Settings 关闭“Start AI Agent on boot”，该明确选择会被保留，不会被固件强制覆盖。
交互延迟：常接电的 Davie 固件会让 Wi-Fi 保持低延迟性能模式，显示屏仍可按原策略休眠。实测空闲网络平均往返从约 460ms 降至约 4.3ms；这能改善唤醒后的首包和远程控制，但不等于本地模型生成本身只需 4ms。
慢在哪里可以查清：Gateway 0.3.11 会按回合记录输入音频、ASR、首个非空文本 delta、Davie、每段 TTS、首音频、首音频后的非播放空隙和总耗时。Davie 的第一句会在后续文字生成期间提前进入 TTS，下一句也会在当前声音播放时预先合成。维护时应先查看 last_turn_timing，再决定优化端点、模型还是语音合成，避免为了“快”而缩短自然停顿或降低答案质量。
中英文如何处理：每个语音回合会根据当前转写单独确定回答语言，不修改你的原话，也不改长期偏好。纯英文默认用英文，纯中文默认用中文，中英混合按主要语言回答并保留待解释的原词。若 Hermes 流式接口正常结束却没有正文，Gateway 只会在没有工具或进度事件时安全重试一次非流式请求。

伴读如何使用

书籍或文章由 Davie、Web、Telegram 或其他客户端通过认证 API 装载到 Gateway。内容和句子级进度保存在 Gateway，不依赖 TF 卡，设备重启后仍可继续。TF 卡未来可用于离线书库，但不是当前接入的必要条件。

内容可以在 Stack-chan 空闲或离线时预先装载。需要设备立即开口、拍照或执行硬件动作时，请在空闲状态说 Davie 建立当前会话；这是官方 1.4.3 的按需连接设计。进入 Listening 后会持续听取后续需求，不需要每句话重复唤醒词；说 “Goodbye Davie” 或长时间不使用后会回到待命。

边界

  • 摄像头是 0.3 MP，适合近距离物体和清晰大字，不适合远处小字或复杂扫描件。
  • 空闲时说 “Davie”，等待 Listening 状态后再说需求；Listening 状态下直接讲话。
  • 远程立即说话、拍照或控制硬件需要设备处于已连接的 Davie 会话；离线装载的伴读内容会保留。
  • 语音、网络或模型服务不可用时，设备会明确提示，不会假装完成硬件动作。
  • 设备已加载唯一的 “Davie” 唤醒命令；真人近距离识别率、房间噪声误触发和播放中打断仍应在实际摆放位置做最终验收。

如果屏幕说没有听清

刚进入 Listening 后的第一次空转写不会再立即显示失败，设备会继续等待你自然开始讲话。非实时模式只有连续两次没有识别到文字才提示 I did not catch that. Please try again.；中间只要听到非空内容，连续计数就会归零。若仍反复出现提示，请先靠近设备、等 Listening 稳定后说完整短句，再让 Davie 查询最近会话中的 ASR 质量证据。

实时状态不要靠知识库猜：Knowledge Atlas 记录的是能力和历史。询问机器人此刻是否在线、醒着或可用时，Davie 必须调用 stackchan_status；Gateway 可达不等于物理设备已经建立语音会话。
