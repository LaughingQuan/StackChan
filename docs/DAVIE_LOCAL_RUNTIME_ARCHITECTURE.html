Architecture contract · 2026-07-22

Official core.
Local Davie.

以 M5Stack 官方 Stack-chan 1.4.3 公开源码为硬件与交互基线，只增加可关闭、可测试、可替换的 Davie 本地运行时适配层。

UPSTREAM-FIRST

不可破坏的原则

凡是官方已经实现并可满足需求的功能，直接复用。只有官方没有提供接口或行为不满足验收合同时，才允许增加最小桥接补丁。

官方所有

AEC、VAD、WakeNet、双麦克风、Opus、音频编解码、摄像头、屏幕、表情、舵机、BLE 配网、Wi-Fi、OTA 与设备状态机。

Davie 所有

会话、记忆、工具、知识库、任务编排、深度模型路由、书籍进度与跨设备连续性。

Adapter 所有

官方 WebSocket/Opus/MCP 合同与 Davie 事件之间的转换、generation、播放回执、打断回执和摄像头请求。

本地配置所有

Wi-Fi、Rock5B 地址、设备令牌和服务端点只进入 sdkconfig.defaults.local 或设备 NVS，不进入 Git。

实现顺序

  1. 原样构建官方 1.4.3，并验证屏幕、舵机、摄像头、双麦克风、扬声器、BLE 和官方状态机。
  2. 在 Rock5B 实现兼容官方 WebSocket 协议的 Davie Gateway，先做到固件零改动接入。
  3. 验证双向 Opus、设备 AEC、播放中 abort、STT/LLM/TTS 状态和 MCP 工具发现。
  4. 以官方 MultiNet5 English Q8 实现本地 “Davie” 命令识别，并保留真人近场声学验收门槛。
  5. 复用官方 AI Agent 入口，在 Davie 构建中仅将标签改为 DAVIE；阅读、拍照解释、提醒、状态和运动能力通过语音与官方 MCP 工具提供，不复制菜单。
  6. 接入 16GB TF 可选缓存；无卡时所有核心功能仍通过网络工作。
  7. 完成断网、重连、长时间播放、打断、双讲、摄像头和恢复镜像验收后再发布。

当前实现状态

能力状态证据边界

TF 卡可选当前核心功能不依赖 TF 卡；后续仅用于书籍缓存和离线进度

升级流程

origin 指向 LaughingQuan fork，upstream 只允许 fetch。升级时先同步官方分支，再 rebase feat/davie-local-runtime，最后依次执行官方测试、协议 fixture、固件构建和实体设备回归。

设备原厂 1.4.4 的完整 16MB 镜像继续作为恢复与差异对照，不将公开 1.4.3 源码错误标记成 1.4.4。
